### The three root causes closed this session

**1. Watchdog kills (`0x8BADF00D` ×5 on Jeff's 09-01 09:00 drive).**
Root cause, from the `.ips` stacks + `@rnmapbox` source: **any per-tick change to a layer
`style`/`filter` prop is a full main-thread read-modify-write** (`RNMBXLayer.reactStyle
didSet → StyleManager.updateLayer`; there is no style diff). The route ribbon was pushing
`lineTrimOffset` + a re-baked congestion gradient at 12 Hz across three layers per surface,
on one main thread shared by phone and CarPlay. Fix: **per-tick state now lives in the
SOURCE** — `src/routeRibbon.ts` (new) cuts ribbon geometry at the car and carries
colour/alpha per feature; the self-car marker's heading rides its source feature.
Verified after the fix by an 8 s / 1 ms `sample` while navigating at 100 km/h through
bends: `getStyleLayerProperties` **0 hits**. The same mechanism was the "Show map froze
the phone and CarPlay" report — one main thread, two surfaces.
**Rule now in `CLAUDE.md`: nothing that moves per tick may be a layer property.**

**2. Weather died on every surface for ~20 h / 13 OTAs.**
A bare `eas update` bakes an **empty** `EXPO_PUBLIC_OPENWEATHER_KEY` (`PROD_OPENWEATHER_KEY`
is `""` in `src/api.ts`; the real key exists only in the EAS environment). Silent — no error,
just no weather. **The OTA ritual is now mandatory:**
```bash
npx eas-cli env:exec preview "npx eas-cli update --branch mapbox-migration --clear-cache -m '<msg>' --non-interactive"
python3 tools/ota/verify-bundle-key.py <group> 1.26.0     # expect KEY_PRESENT=1 on BOTH
```
`tools/ota/ow.key` is gitignored and regenerated with
`npx eas-cli env:exec preview 'printf "%s" "$EXPO_PUBLIC_OPENWEATHER_KEY" > ow.key'`.
This is enforced in `.claude/skills/ship-ota/SKILL.md`.

**3. `yarn typecheck` — the OTA gate — was RED and nobody noticed.**
The new Deno worker sources under `supabase/` were swept into the app's `tsconfig.json`
`include`, producing **111 errors**. Fixed by adding `"exclude": ["supabase"]` (Deno checks
those itself via `deno task check`). `yarn typecheck` now exits 0. **If a future session
adds server-side TS, exclude it too.**

## 6 · Today's drives — and a caveat you must read first

### ⚠ The `main-gap` instrument cannot yet distinguish a freeze from a suspension

Two independent reasons, both verified in code:

**(a) The loop it samples is not free-running.** `noteFrame` has exactly ONE caller —
`src/ConvoyMapbox.tsx:1446`, inside the SelfCarModel animation step. That loop *stops*
when the ease ends and is not re-armed on the GPS jitter dead-band. So a "gap" can simply
be **the animation loop not running**, with the main thread perfectly healthy. `main-gap`
does not prove a stall.

**(b) `app=` is sampled after the fact.** `src/heatProbe.ts:181` emits from inside
`noteFrame`, i.e. only when a frame finally arrives; `app=` is `_appSeen.slice(-1)`, the
most recent `AppState`. A phone that slept and woke reports `app=a` exactly like one that
froze. Threshold `GAP_ALERT_MS = 2000`, rate-limited to one row per 10 s — so a row count
is a **floor**, not a count.

Also: `surface=car` means "a head unit was connected", not "the car map stalled".

Today's rows make the problem obvious: **8 gaps of 60 s or more on `surface=car` with
`app=a`, the largest 866,221 ms — 14.4 minutes.** An app whose main thread is genuinely
blocked for 14 minutes is killed by the OS watchdog in ~20 s. Those are phone-lock /
JS-suspension, not stalls (HYPOTHESIS, but physically near-certain, and consistent with
the known iOS behaviour recorded in `carplay-dead-buttons-root-cause`).

**Do not report these numbers to Jeff as freezes without the discriminator.**

**The fix (OTA-able, small):** (1) log the whole `_appSeen` sequence instead of its last
character (`'aba'` = active→background→active proves a suspension); (2) add ms since the
last `AppState` change; (3) emit from a source that runs unconditionally, or tag rows with
whether the step loop was armed. Until then treat every figure below as an upper bound on
badness, not a measurement. **Candidate for the real Android stalls:** the road-snap path
calls `querySourceFeatures` (`src/ConvoyMapbox.tsx:2226`) on the road source — profile
that before anything else.
